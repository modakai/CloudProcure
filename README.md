# 云采 CloudProcure：企业采购与履约微服务实战

文档版本：v1.1 设计基线｜更新日期：2026-10-20｜状态：待实现、待技术验证。

面向个人学习与作品集，设计一个平台自营、面向多家企业客户的采购系统。通过真实的审批、订单、库存、支付、退款和履约约束学习微服务，而不是做一组互相调用的 CRUD。

**当前已交付产品工程设计和可编译运行的八应用骨架，尚未实现采购业务与OIDC认证闭环。文中的容量、SLO、进度仍为设计目标或估算，不能当成实测结果或生产承诺。**

快速开始：使用本机Maven3.9.9与JDK21，在根目录运行`mvn -B -ntp verify`，单独启动前先运行`mvn -B -ntp -pl common/common-webmvc -am install -DskipTests`安装公共库，再运行`mvn -pl gateway "-Dspring-boot.run.profiles=skeleton" spring-boot:run`；显式`skeleton`模式无需中间件，仅开放`http://127.0.0.1:8080/actuator/health`。不使用Maven Wrapper；当前默认`local`需要个人配置和真实依赖。测试源码按维护者要求仅保留本地，干净克隆的`verify`不代表已执行测试。完整命令见[骨架搭建与启动指南](docs/14-骨架搭建与启动指南.md)，验证结果与依赖证据见[#2验证报告](docs/evidence/M0-issue-2/README.md)。

## 先读这六条结论

1. 最新已发布稳定 SCA 核验为 **2025.1.0.0**；发布参考为 Spring Cloud 2025.1.0、Spring Boot 4.0.0。实际实施候选采用 Cloud 2025.1.3、Boot 4.0.8、JDK 21，须先验证。详情见版本文档；不将开发分支、SNAPSHOT 或 BOM 客户端版本当作服务器兼容承诺。
2. 六个业务服务（组织权限、商品、交易、库存、支付、履约）加一个自建identity-service和一个网关。identity基于Spring Security 7的授权服务器能力提供OIDC；Gateway保留OAuth2 Client，业务服务使用Resource Server。不手写协议处理器，不将多个微服务等同多个SSO系统。
3. 核心路径采用本地事务、Outbox/Inbox、显式业务编排和补偿。Seata 在独立实验中学习，不强行包住异步支付和物流。
4. 首版只做单运营主体、单币种人民币、单仓、单级审批、整单付款、发货前整单退款。真实支付、电子发票、多供应商结算均不属于首版。
5. 企业级质量看边界与证据：租户越权必须被拦截；重复请求不能重复扣库存或退款；未知支付结果必须可对账；数据库必须可恢复。
6. 业务持久化采用Spring Data JPA/Hibernate，底层仍使用JDBC；关键库存/状态更新显式校验并发条件。认证协议数据优先复用框架提供的JDBC存储，不为统一ORM而重写框架仓储。

## 推荐阅读与实施顺序

先看 PRD 和需求确定业务，再读版本基线完成兼容性 POC，随后按架构、数据、接口、一致性实施。安全与验收从第一个迭代生效，不能留到最后。运维文档随每次交付更新。

推荐演示：企业 A 采购员提交申请 → 审批人批准 → 锁库存 → 财务模拟付款 → 仓库发货 → 采购员收货；再演示重复回调、缺货、超时取消、退款和企业 B 越权被拒绝。
