# 版本基线与官方依据

> 调研日期：2026-10-20（Asia/Shanghai）。本章属于设计依据，不代表依赖已经构建通过、集群已经部署或安全扫描已经通过。

骨架实施进展：候选Boot4.0.8/Cloud2025.1.3/SCA2025.1.0.0已通过八应用编译、默认配置启动与HTTP安全兜底测试；完整联调和安全门禁未完成，详见[验证记录](evidence/M0-skeleton.md)。

## 1. 结论与选型口径

本项目采用 **Spring Cloud Alibaba 2025.1.0.0 正式版**作为主线。查询时，官方 GitHub `releases/latest` 指向该版本，Maven Central 也存在对应 BOM；不能因为版本号包含 2025 就推断它不是当前正式版本。[S1][S2]

“最新”必须拆成三个问题：SCA 最新正式发布是什么、它发布时基于什么组合、项目实际准备验证什么组合。三个答案不必相同。不能将所有独立组件的最新版本直接相加，并把它描述成“官方验证的企业级技术栈”。

### 1.1 两层版本表

| 层次 | SCA | Spring Cloud | Spring Boot | Java | 状态与用途 |
| --- | --- | --- | --- | --- | --- |
| 官方发布参考组合 | 2025.1.0.0 | 2025.1.0 | 4.0.0 | 最低 17 | 已核对 Release / 固定 tag；用于定位适配边界，不作为生产安全承诺 |
| 项目实现候选组合 | 2025.1.0.0 | 2025.1.3 | 4.0.8 | JDK 21 LTS | Cloud / Boot 版本来自当前官方页面；必须通过 P0 兼容性验证后冻结 |
| 后续升级候选 | 2025.1.0.0 或后续正式版 | 2025.1.x | 4.1.x | JDK 21 或经验证的后续 LTS | Cloud 矩阵允许不等于 SCA 所有 starter 已经过联合验证；不作为首轮实施默认 |

官方 Release 明确记录从 Boot 3.5.0 升至 4.0.0、Cloud 2025.0.0 升至 2025.1.0。当前 Spring Cloud 官网显示 2025.1.3，并将 2025.1.x 对应到 Boot 4.0.x，以及从 Cloud 2025.1.2 开始支持的 Boot 4.1.x。因此，第二行是**有官方代际依据的工程候选**，不是伪造的 SCA 联合认证矩阵。[S1][S3]

Boot 4.0 系列系统要求页面查询时对应 4.0.8，最低 Java 17；JDK 21 是本项目为了稳定工具链作出的设计选择，不是 Boot 4 强制要求。[S4]

### 1.2 明确排除的混淆

- `2025.1.0.1-SNAPSHOT` 是开发快照，不作为交付基线。开发分支上的 Boot / Cloud 升级不代表已发布 SCA BOM 自动获得同样承诺。
- `M`、`RC`、`SNAPSHOT` 不等于正式版。Boot 页面中的独立最新稳定版、预览版，不能直接推导为本项目的适配版本。
- Spring Cloud Alibaba 与 Spring AI Alibaba 是不同项目；不能拿 Spring AI Alibaba 的版本表证明 SCA 兼容性。
- Boot 3.x 教程中的 starter、`bootstrap.yml`、Jackson、Servlet 适配经验，不可原样迁入 Boot 4 主线。

依据：固定版本 Release、SCA 开发分支 POM、Boot 官方版本导航。[S1][S4][S5]

## 2. SCA BOM 中间件版本与服务端边界

以下客户端值逐项取自 **2025.1.0.0 固定 tag 的 `spring-cloud-alibaba-dependencies/pom.xml`**，不是从博客或主分支猜测。[S6]

| 组件 | SCA BOM 管理的客户端/集成版本 | 本项目部署建议 | 验证边界 |
| --- | --- | --- | --- |
| Nacos | `nacos-client:3.1.1` | 首轮可复现环境采用 Server 3.1.2；将 3.2.4 作为升级候选 | 3.1.2 来自 v3.1 官方推荐；3.2.4 是查询时 GitHub latest。客户端兼容与 OpenAPI 兼容分开验证 |
| Sentinel | `1.8.9` | SDK 与实验 Dashboard 保持 1.8.9；独立最新 1.8.10 留待回归 | 规则持久化、Gateway 适配、Jackson 与故障行为必须实测 |
| Seata | `2.5.0`，`org.apache.seata:seata-spring-boot-starter` | 仅隔离实验部署 Server 2.5.0；后续 2.6.0 单独评估 | 主业务闭环不依赖 Seata；不得把 XA / AT / TCC 混作同一种事务保证 |
| RocketMQ | `org.apache.rocketmq:rocketmq-client:5.3.1` | 首轮兼容性实验 Server 5.3.1；生产候选评估 5.5.1 | BOM 值是 Remoting 客户端，不是 gRPC Java SDK；Broker HA、鉴权与重投语义另验 |

上述部署版本用于建立可复现起点。**旧补丁与客户端同号不是安全保证；新服务端也不是默认已兼容。** 进入预生产前必须选定仍被维护且漏洞门禁通过的服务端补丁，记录镜像 digest、客户端依赖树与回归报告。若起点版本存在不可接受漏洞，直接阻止上线，不能为了“与教程一致”保留。

Nacos 官方 v3.1 升级手册说明 3.x 服务端兼容 2.x / 3.x 客户端，但 HTTP OpenAPI 的代际变化有独立说明。该兼容表不能替代本项目配置导入、鉴权、实例上下线和网络端口验证。[S7][S8][S9]

独立最新 Release 的查询结果为 Nacos 3.2.4、Sentinel 1.8.10、Seata 2.6.0、RocketMQ 5.5.1；这些事实仅说明各自项目的发布状态，不构成 SCA BOM 升级指令。[S10][S11][S12][S13]

## 3. 已发现的集成陷阱

### 3.1 Nacos 配置不再沿用 bootstrap 模式

SCA 2025.1.0.0 Release 明确移除 bootstrap 配置支持，统一使用 `spring.config.import`。新项目在 `application.yml` 中明确导入必需配置；关键安全/数据库配置缺失时应启动失败。`optional:nacos:` 只允许用于明确可选且有安全默认值的配置。[S1]

环境、命名空间、分组、Data ID、客户端身份必须进入配置清单。命名空间负责运维环境分隔，不作为业务租户鉴权边界。

### 3.2 MyBatis starter 不能直接继承 BOM 默认值

固定 SCA BOM 仍管理 `mybatis-spring-boot-starter:3.0.5`。MyBatis 官方兼容表将 starter 3.0 对应到 Boot 3.2–3.5，将 starter 4.0 对应到 Boot 4.0+。[S6][S14]

经用户确认，业务持久化采用Spring Data JPA/Hibernate、HikariCP与Flyway，由Boot依赖管理解析兼容版本；不手工把Spring Data或Hibernate独立最新版覆盖进来。JPA底层仍使用JDBC，并不改变本地事务、唯一约束和条件更新要求。认证协议仓储优先复用Spring Security提供的JDBC实现，业务账号使用JPA。若以后选择MyBatis，必须显式使用经验证的4.0系列starter；第三方扩展也不因MyBatis兼容而自动兼容。

### 3.3 自建OIDC与Spring Security代际

身份方案改为基于Spring Security 7授权服务器能力自建identity-service，不部署Keycloak、不采用Sa-Token主线。Gateway作为OAuth2 Client，业务服务作为Resource Server。Spring Authorization Server已并入Spring Security 7，使用Boot管理的授权服务器Starter及一致的Security版本，不直接拼入旧教程独立1.x依赖。参见[官方迁移说明](https://spring.io/blog/2025/09/11/spring-authorization-server-moving-to-spring-security-7-0/)与[7.0入门](https://docs.spring.io/spring-security/reference/7.0/servlet/oauth2/authorization-server/getting-started.html)。具体服务范围见[认证设计](13-自建OIDC认证服务设计.md)，尚未构建验证。

### 3.4 RocketMQ 服务端 5.x 与 gRPC SDK 不是同一概念

BOM 管理的 `rocketmq-client` 与官方文档中的 `rocketmq-client-java` 是不同客户端路线。官方 gRPC Java SDK 要求至少 5.0 服务端并启用 gRPC Proxy；Remoting SDK 采用对应的连接与部署方式。[S6][S15]

本项目首先使用 SCA Stream RocketMQ binder 对应的 Remoting 路线验证普通业务事件；不得将其 endpoint 指向 gRPC Proxy 并认为已经完成升级。事务消息、定时消息、顺序消息必须逐项确认 binder 能力与配置；默认的超时关单以数据库截止时间及补偿扫描兜底，不能依赖未经验证的延迟能力。

### 3.5 Sentinel Dashboard 不是自动持久化的治理平台

官方说明默认控制台规则保存在内存，生产建议使用动态规则数据源与 push 模式。[S16]

本项目将经审核的规则保存在 Nacos，发布工具/流水线负责写入，应用负责读取。Dashboard 首轮用于观测和实验；只有完成控制台规则发布改造及鉴权后，才允许成为正式规则编辑入口。必须演练“应用重启后规则仍生效”和“配置中心不可用时保留最后有效规则”。

### 3.6 Seata 支持声明不能代替业务正确性

本次 Release 包含 Seata 自动配置失败的修复及 WebFlux 支持，说明相关适配点值得单独验证。[S1]

项目订单、库存、支付主链路采用本地事务、Outbox、幂等与补偿。Seata 仅作为对照实验：固定数据库、驱动、代理方式、事务模式，测量异常回滚与锁冲突。不得将跨第三方支付的结果纳入本地数据库分布式事务承诺。

## 4. 证据可信度与检索交叉检查

本次使用官方 Web 页面、固定 Git tag 源码、Maven Central 与 Context7 交叉检查。Context7 解析到库 `/alibaba/spring-cloud-alibaba`，并查询了固定版本 `/alibaba/spring-cloud-alibaba/2025.1.0.0` 的版本/配置资料。

Context7 返回片段同时存在固定 tag README 示例版本较旧、开发分支代码较新的情况。因此它用于定位证据，不作为唯一版本判定依据；最终 BOM 值以固定 tag 源码和发布制品页面为准。搜索摘要里的爬取时间、GitHub 页面简写日期不作为精确发布日期。

| 核验事项 | 当前结论 | 证据状态 |
| --- | --- | --- |
| SCA 最新正式版 | 2025.1.0.0 | 官方 latest 重定向与中央仓库交叉核对 |
| 发布时 Boot / Cloud | 4.0.0 / 2025.1.0 | 固定 Release 已核对 |
| 候选 Boot / Cloud 代际兼容 | 4.0.8 / 2025.1.3 属于官网支持代际 | 已核对；尚未与 SCA 联合运行 |
| BOM 客户端值 | Nacos 3.1.1 / Sentinel 1.8.9 / Seata 2.5.0 / RocketMQ 5.3.1 | 固定 tag 已核对 |
| 骨架依赖解析与基本装配 | 八应用构建及HTTP冒烟通过；不等于全部依赖行为无冲突 | 已运行Maven verify，真实中间件及协议仍待联调 |
| 所有客户端与部署服务器兼容 | 尚不能下结论 | 待 P0 集成测试 |
| 无漏洞、可生产使用 | 尚不能下结论 | 待 SCA / SBOM / 镜像与配置扫描 |
| 吞吐与延迟达标 | 尚不能下结论 | 待真实环境压测 |

## 5. 开发前 P0 门禁：通过才冻结工程版本

| 编号 | 验证项目 | 最低通过标准 | 失败处理 |
| --- | --- | --- | --- |
| V-01 | Maven 解析与依赖收敛 | 固定 wrapper/JDK；生成 effective POM、dependency tree；无意外 Boot 3 / Spring 6 starter | 修正 BOM 顺序或替换不兼容 starter，禁止通过关闭校验掩盖 |
| V-02 | Nacos 注册与配置 | 双实例注册、发现、摘除；配置更新、鉴权失败、缺少必需配置均符合预期 | 阻止候选版本进入业务开发基线 |
| V-03 | 自建identity、Gateway与安全 | 完成单客户端Code+PKCE、Token校验、授权和密钥持久化、重启、退出；网关无阻塞调用；详见TC-027～030 | 回到最小认证链路定位，不以关闭验签/PKCE绕过 |
| V-04 | JPA与协议JDBC存储 | 实际MySQL迁移、JPA事务/乐观锁/条件更新、唯一约束、认证JDBC表与连接池验证通过 | 修正Boot管理依赖、映射或迁移，禁止自动改生产表 |
| V-05 | Sentinel | 触发限流/熔断、正确恢复、规则跨重启保留 | 暂缓控制台写入，保留配置源发布 |
| V-06 | RocketMQ | 生产、消费、重复、重试、死信、Broker 重启恢复全部验证 | 固定协议与 SDK，剥离未经支持的消息特性 |
| V-07 | 链路追踪 | HTTP→事件→消费者可关联，日志不泄露令牌或个人敏感字段 | 修正 instrumentation 与上下文传播 |
| V-08 | 依赖与镜像安全 | 形成 SBOM；严重风险有修复或明确且可接受的处置 | 阻止发布，而非默认沿用早期补丁 |
| V-09 | Seata 对照实验 | 若启用，证明故障回滚/补偿与锁行为，单独记录配置 | 不影响不依赖 Seata 的主闭环交付 |

冻结产物应包括：精确版本表、制品坐标、依赖树、容器 digest、配置模板、上述报告和回滚步骤。以后每次升级先更新本章证据，再运行受影响的门禁。生产环境不使用 `latest` 标签或 SNAPSHOT 依赖。
