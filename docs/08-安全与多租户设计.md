# 08 安全、权限与多租户

版本：v1.1｜安全要求从M1实施，不作为最后补丁。本文是工程设计，未进行渗透测试或法律合规认定。账号与协议细节见[自建OIDC设计](13-自建OIDC认证服务设计.md)。

## 1. 身份与信任边界

浏览器不可信，网关不是唯一授权点，服务网络也不自动可信。identity-service基于Spring Security 7授权服务器能力承担账号、密码、MFA与OIDC Token，协议处理复用框架；access负责企业成员和业务授权。当前仅一个采购门户客户端，不以多个微服务推导SSO需求。平台高权限账号P1启用TOTP并验证恢复流程，未完成前只允许本地合成数据演示。

Web采用Gateway兼任BFF：Authorization Code + PKCE，服务端保存访问/刷新Token，浏览器只持有Secure、HttpOnly、合适SameSite策略的会话Cookie。配置state、nonce、精确redirect URI、会话固定防护、CSRF保护和允许来源。跨站回调与SameSite策略通过实际OIDC流程测试，不能为了能登录就全局关闭CSRF。

设计参考[OAuth安全最佳实践 RFC 9700](https://www.rfc-editor.org/rfc/rfc9700.html)与[浏览器应用OAuth最佳实践 RFC 10017](https://www.rfc-editor.org/rfc/rfc10017.html)。BFF是本项目降低浏览器Token暴露面的选择，不能因此省略XSS、CSRF或服务端授权。

每个下游服务校验签名、发行方、受众、时效及允许算法，Token不可仅解码不验签。面向不同服务的受众配置与委托策略在M0验证；用户Token缺少正确aud不能靠关闭校验解决。服务身份与用户身份区分：服务凭据证明调用者是谁，用户上下文证明它代表谁，二者均不授予任意租户访问权。

## 2. 企业上下文与即时撤权

企业选择由用户提出，最终由access判定subject在该企业的有效成员身份。禁止相信客户端的X-User-Id、X-Roles、X-Tenant-Id。网关移除可伪造身份头，下游仍使用可验证身份和授权决策。

高危操作（成员角色、审批、付款、退款、库存调整、发货）每次实时查identity全局账号状态/凭据版本及access有效成员与权限；Token凭据版本不一致或任一校验不可用则失败关闭。低风险查询的账号状态和授权缓存最多60秒。成员或账号停用后下一写请求必须失败，不能依赖JWT自然过期。内部纯服务任务不冒充用户，按批准的服务scope及不可变单据执行。

用户退出时销毁门户会话、清除保存的Token并撤销对应刷新凭据，再完成identity会话退出。短期自包含Access Token可能仍有效至到期；首版有效期候选5分钟，不承诺所有旧JWT立即作废。密码重置/全局停用还需撤销该用户授权与身份会话，高危写仍实时检查账号状态。具体故障与重试见认证设计。

后台已授权业务任务不依赖操作者Token永久有效：付款和补偿任务凭服务身份执行，核对原始授权记录和不可变单据；成员离职不能让已经收款的订单永远无法退款。企业停用阻止新业务；已付订单履约/退款由受控平台支持按工单处理，不能直接跨租户接管。

## 3. 数据隔离矩阵

| 资源 | 边界 | 防护 |
|---|---|---|
| 企业、成员、申请、订单 | 买家企业私有 | tenant_id条件、成员有效性、资源权限 |
| 付款、退款 | 买家归属+财务角色 | 服务端单据关联、金额快照、审计 |
| 平台商品与库存余额 | 平台共有资产 | 平台操作权限，买家只读可售视图 |
| 库存预占、履约单 | 平台资产操作+买方归属 | 内部命令核对订单归属，平台仅看必要资料 |
| Redis缓存 | 按资源性质区分 | 私有键必须包含tenant和数据范围，禁止只用orderId作授权缓存 |
| 对象存储（未来） | 企业私有附件 | 私有桶、短期签名URL、下载再次校验归属 |
| 事件/报表/导出 | 原业务权限仍适用 | 生产者ACL、payload归属验证、读取投影时再授权 |

查询采用tenant_id与resource_id共同定位；子资源必须回查父对象归属。统一查询拦截器只能辅助，不能证明所有原生SQL、批处理和管理员接口已正确隔离。跨租户测试要覆盖列表、详情、修改、批量操作、缓存、事件及异常单。

平台支持使用限时support_grant，绑定企业、工单和操作范围。普通平台账号默认不能查看全部买家PII；高危支持操作必须复核并强审计。

## 4. 业务授权底线

- 申请人不得自批；审批人必须是申请快照指定且当前仍有权限的人。离职任务由管理员审计后重新分派，保留原分派记录。
- 企业管理员不天然拥有财务付款权限；平台商品运营不天然拥有库存调整权限。
- 财务不能更改订单金额；仓库不能标记付款成功；支持人员不能直接覆盖渠道结果。
- 付款和退款操作绑定订单、金额与币种快照，不从页面参数生成权威资金值。
- 高风险角色授予、库存大额调整、模拟生产的人工资金补偿需要双人复核流程；个人演示可演示两个角色，不能宣称真实职责分离已完成。

## 5. 外部回调与入口防护

渠道回调按官方协议验签，验证时间窗口、事件/请求唯一号、商户号、币种、金额、订单映射与状态。先保存可信接收记录及待处理任务，再应答；渠道查询作为丢回调的恢复途径。合法重放通过幂等返回既有结果，不重复记账。签名正确但金额异常进入差异单并告警。

模拟渠道的测试签名密钥只用于本地，故障开关和“模拟成功”入口在非开发环境拒绝启动。未来真实渠道必须另作官方API核验、商户认证和安全评审。

入口设置请求体大小、字段长度、分页上限、登录/下单/回调速率限制。SQL参数化；禁止拼接排序字段，排序使用白名单。禁止任意URL回调配置以降低SSRF面。首版不做文件上传，未来开放时需校验类型、大小、恶意内容及存储权限。

Nacos、数据库、Redis、RocketMQ、Sentinel管理台、Actuator与监控仅内网可达。Actuator只开放最小健康和指标能力，不公开env、配置、heapdump等敏感端点。开发环境也修改默认密码，不把管理口直接映射到公网。

## 6. 密钥、个人信息与审计

Git只保存变量名和空模板。密码、私钥、渠道Secret从环境或受控Secret存储注入，Nacos只存非敏感配置或密钥引用。Dev/Test/Prod密钥独立；记录轮换办法与应急撤销。

日志默认不记录Token、Cookie、支付原始密钥、完整地址和手机号。审计记录操作者、企业/平台范围、动作、对象、结果、时间、traceId和脱敏差异；不能把整份用户资料序列化到日志。

退租/注销不等于删除订单与资金证据。建立保留、脱敏、访问限制和到期销毁策略；涉及真实个人信息、资金和税务时由适用地区合规要求重新评估，文档不预设法律结论。

## 7. 安全交付门禁

依赖与容器漏洞扫描、Secret扫描、关键权限负向用例、CSRF与会话校验、跨租户用例、管理口暴露检查均需证据。发现可利用高危漏洞不得用“最新框架”作为豁免理由；补丁升级仍需跑兼容性与业务回归。
