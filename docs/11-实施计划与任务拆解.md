# 11 实施计划、任务拆解与学习路径

版本：v1.1｜面向个人。估算前提：已熟悉Java、HTTP、SQL与基本Spring；每周投入12～18小时。含可选实验约210～316小时，按实际投入约12～27周；新手可能更久，不能把估算当交付承诺。新增自建OIDC、JPA验证、账号安全和MFA工作，相比v1.0增加约36～52小时。

## 1. 分阶段交付

当前进展：已完成八应用Maven骨架、基础依赖与安全兜底。原有[M0骨架记录](evidence/M0-skeleton.md)仅作历史参考，当前本地Maven构建、私有验证测试与依赖证据见[#2验证报告](evidence/M0-issue-2/README.md)。测试源码按维护者要求不上传GitHub，干净克隆不能自动复现私有测试。identity协议持久化、真实中间件、服务身份与其余门禁仍待完成，不将M0整体标为已完成。

## 3. 每阶段必须回答的问题

M0：你能解释客户端版本和服务器版本为何不必相同吗？你有没有看effective POM而不是只看根pom？

M1：只改tenant头为什么进不了其他企业？成员停用后旧会话为什么不能付款？ID Token为什么不能访问订单？退出后已签发JWT为何可能仍有效？JPA批量更新为何需要显式处理版本与缓存？

M2：数据库提交成功但MQ发送失败时订单在哪？库存是否真的不会超卖？

M3：支付超时为什么不能直接关单？你怎样证明不会重复扣款？

M4：退款先调用渠道会出现什么竞态？仓库发货与冻结谁说了算？

M5：数据库恢复后如何判断支付和库存没漂移？错误率正常但业务卡住时看哪个指标？

如果只能背组件定义却答不出这些问题，先补实验，不要继续堆技术。
