# 限流公共模块（common-rate-limit）

日期：2026-11-02｜状态：阶段 1 已实现并完成本机单元测试与 Docker Redis 集成测试｜对应任务：[Issue #12](https://github.com/modakai/CloudProcure/issues/12) 阶段 1

本模块把“Redis 原子限流”收敛为一组公共 API：`@RateLimit` 注解 + AOP、程序化 `RateLimiter`、四种算法、键解析、自动配置与配置元数据。identity 登录限速迁移（阶段 2）不在本次范围。

## 1. 范围与不做什么

本模块负责：

- Spring Bean 方法上的 `@RateLimit` 拦截；
- 供 Servlet Filter、Spring Security、消息消费者调用的程序化 `RateLimiter`；
- Redis 单键 Lua 原子判定，支持固定窗口、滑动窗口、令牌桶、漏桶；
- key 的命名空间、维度、摘要、长度/字符校验；
- 配置、自动配置、退让点、配置元数据与控制台决策日志。

本模块**不**负责：

- WebFlux 事件循环上的限流。实现使用阻塞 Redis API，不能在事件循环线程调用；
- 分布式锁、验证码、永久账号锁定、自动解封；
- 多 key 跨槽原子事务、Redis Cluster/Sentinel 的故障转移验证；
- 代理来源 IP 信任模型；来源地址是否可信由调用方决定；
- 把 `allowed=false` 自动翻译成 429、把 `RateLimitUnavailableException` 自动翻译成 503。模块不依赖 MVC/Security，映射由调用方完成；
- 生产容量、压测、SLO 结论。

## 2. 接入

服务通过 `common-bom` 取得版本，不手写 `${project.version}`：

```xml
<dependency>
    <groupId>com.cloudprocure</groupId>
    <artifactId>common-rate-limit</artifactId>
</dependency>
```

只要引入依赖且 `cloudprocure.rate-limit.enabled` 未显式关闭，自动配置就会要求一个 `StringRedisTemplate`。**缺少 Redis 时应用启动失败**，而不是静默地“没有限流”；确实不需要限流的应用必须显式设置 `enabled=false`。

典型配置：

```yaml
spring:
  application:
    name: identity-service
  data:
    redis:
      host: 127.0.0.1
      port: 6379
      password: ${REDIS_PASSWORD}
      timeout: 2s

cloudprocure:
  rate-limit:
    enabled: true
    # 未配置时取第一个 active profile，仍没有则用 default 并打印 WARN。
    environment: local
    # 未配置时读取 spring.application.name；两者都没有则启动失败。
    # application: identity-service
    # 配置后整体覆盖 environment/application 拼接；建议以冒号结尾，缺失时自动补。
    # key-prefix: cp:local:identity-service:rate-limit:v1:
    default-limit: 100
    default-window: 1m
    default-algorithm: FIXED_WINDOW
    max-limit: 100000
    max-window: 1d
    max-key-length: 512
    max-identifier-length: 512
    # 默认打印允许/拒绝决策；生产高流量环境建议设为 false。
    log-decisions: true
    # 默认高于事务拦截器，让超限请求在数据库之前失败。
    aop-order: -2147483548
```

`default-algorithm` 可取 `FIXED_WINDOW`、`SLIDING_WINDOW`、`TOKEN_BUCKET`、`LEAKY_BUCKET`，不能取 `DEFAULT`。

## 3. 注解用法

```java
@RestController
class LoginController {

    @RateLimit(
            key = "#loginName",
            limit = 5,
            window = "5m",
            algorithm = RateLimitAlgorithm.SLIDING_WINDOW,
            prefix = "identity:login",
            dimension = "account")
    @PostMapping("/login")
    String login(String loginName) {
        // ...
    }
}
```

- `key` 是 SpEL 标识表达式，求值结果只作为 `RateLimitKey.identifier`，不会直接拼进 Redis 键。
- `limit=-1` 表示使用全局默认；`window=""` 表示使用全局默认；`algorithm=DEFAULT` 同理。
- 类级 `@RateLimit` 作为方法默认值；方法注解显式设置的属性覆盖类注解，未设置的属性继续继承。
- 方法没有注解时，类注解生效。
- **`window` 是 String，不是 `Duration`**：Java 注解元素不允许 `Duration`，issue 中的 `Duration window()` 无法编译。支持 `5m` 简单写法和 `PT5M` ISO-8601 写法。
- SpEL 使用 `SimpleEvaluationContext` 只读数据绑定：不支持 `@bean`、`T(...)`、构造器或任意方法调用；可读取方法参数和公开属性。参数名依赖 `-parameters`（根 POM 已开启），同时提供 `p0/a0` 位置别名。
- 求值失败、null、空串、未知返回类型都会抛 `RateLimitConfigurationException`，不会退化成所有请求共享的键。

注解只对**可被 Spring 代理**的方法生效。以下情况不生效，文档和测试都明确覆盖：

- 同一个 Bean 内部 self-invocation（A 调 B，B 的注解被绕过）；
- private/final 方法；
- 非 Spring Bean；
- WebFlux 事件循环上的方法；
- 直接在 Filter/Security 链中调用的“方法”（它们不是 Controller 方法）。

这些入口请使用程序化 API。

## 4. 程序化 API

```java
RateLimitResult result = rateLimiter.tryAcquire(
        new RateLimitKey("identity:login", "account", loginName),
        5,
        Duration.ofMinutes(5),
        RateLimitAlgorithm.SLIDING_WINDOW);

if (!result.allowed()) {
    response.setStatus(429);
    response.setHeader(HttpHeaders.RETRY_AFTER,
            Long.toString(result.retryAfterSeconds()));
    return;
}
```

`RateLimiter` 的契约：

- 允许：`allowed=true`，`retryAfterSeconds=0`；
- 拒绝：`allowed=false`，`retryAfterSeconds>=1`；
- Redis 连接失败、认证失败、超时、WRONGTYPE、Lua 错误、损坏状态：抛 `RateLimitUnavailableException`，**绝不返回 allowed**，也不回退内存；
- 调用参数错误：抛 `RateLimitConfigurationException`，属于程序缺陷，不应映射成 429；
- `RateLimitResult.remaining()` 只用于日志/观测，不参与安全判断。

调用方负责把拒绝映射为 429、把不可用映射为 503。模块不写 HTTP 响应，以免被消息消费者或服务层复用时绑定 MVC；映射扩展点就是调用方自己的 `@ExceptionHandler` 或 Servlet Filter。失败策略固定为 fail-closed，不提供 fail-open 开关。

## 5. Redis 键与安全

默认键格式：

```text
cp:<environment>:<application>:rate-limit:v1:<namespace>:<dimension>:<algorithm>:<sha256(identifier)>
```

示例：

```text
cp:local:identity-service:rate-limit:v1:identity:login:account:sliding-window:6f1c...（64 位十六进制）
```

设计约束：

- `namespace`/`dimension` 只允许字母、数字和 `._:$#-`，拒绝空白、控制字符和 Redis 通配符 `* ? [ ]`；长度各不超过 128。
- `identifier` 在摘要前先 trim，不改变大小写；最长 4096，实际部署可用 `max-identifier-length` 收紧。原始标识不写 Redis、不写日志。
- SHA-256 摘要是**去标识化手段，不是匿名化**：用户名、手机号等低熵值仍可能被字典反推；Redis 必须内网可达、启用认证，并与不可信输入隔离。
- 算法段进入键，避免切换算法时把 String 计数当 ZSET/HASH 读取而触发 WRONGTYPE。代价是切换算法会重新获得完整额度，发布时必须接受。
- `key-prefix` 配置会整体覆盖环境/应用拼接；多环境共用一个 Redis 时必须显式包含环境段。
- 键长度超过 `max-key-length` 时拒绝，不会截断（截断会造成不同键碰撞）。
- 一个维度一次脚本。账号 + 来源两个维度是两次独立调用，不是跨键事务，允许保守多消耗；这符合 issue 中“接受保守扣额”的要求。

## 6. 四种算法

| 算法 | Redis 结构 | 允许的突发 | 主要代价 |
|---|---|---|---|
| `FIXED_WINDOW` | String 计数 + TTL | 窗口边界最多 2 倍 | 边界不公平 |
| `SLIDING_WINDOW` | ZSET 时间戳 | 无边界突发 | 每键最多 limit 个成员，内存随额度增长 |
| `TOKEN_BUCKET` | HASH `tokens/ts` | 最多 limit 个令牌的突发 | 需要浮点补充与时钟一致性 |
| `LEAKY_BUCKET` | HASH `level/ts` | 队列满前可突发 | 只做准入，不延迟执行 |

### 固定窗口

一个键一个整数计数器。键不存在时 `SET key 1 PX window`，之后窗口内每获准一次 `INCR`；达到额度后拒绝，拒绝路径不递增、不刷新 TTL。实现最简单，但窗口边界可能通过约两倍额度。

### 滑动窗口

用 ZSET 保存最近一个窗口内获准请求的 Redis 服务器时间（微秒）。每次脚本先 `ZREMRANGEBYSCORE` 删除早于 `now-window` 的成员，再 `ZCARD` 统计；未达额度则 `ZADD` 当前时间戳并刷新 TTL。任意长度为 window 的滚动区间都最多 limit 次，代价是内存与命令数随 limit 增长。

### 令牌桶

桶容量为 limit，按 `limit/window` 的速率补充令牌。每次请求按经过时间补充（不超过容量），有令牌则扣 1 放行，否则按 `(1-tokens)/rate` 计算等待时间。允许容量内的突发，同时限制长期平均速率。

### 漏桶

容量为 limit 的队列，按 `limit/window` 的速率泄漏。请求使 `level+1`，超过容量则拒绝，否则等待 `(level+1-capacity)/rate`。本模块只做准入判定，**不把请求排队延迟执行**；因此它是漏桶计量器，不是流量整形调度器。在“只允许/拒绝”的模型下，它与令牌桶是对偶表达，但状态和失败边界不同。

所有算法都使用 Redis `TIME`，不依赖应用机器时钟；Redis 故障或状态损坏统一 fail-closed。

## 7. 失败语义与日志

- 默认且唯一支持 fail-closed：Redis 不可用、超时、认证失败、WRONGTYPE、Lua 错误、损坏计数/缺失 TTL 都抛 `RateLimitUnavailableException`。不提供 fail-open 开关，避免配置失误造成静默放行。
- 拒绝不进入被保护方法/密码校验；`@RateLimit` 抛 `RateLimitExceededException`，调用方映射 429。
- 不自动重试可能已写入计数的请求；接受保守扣额。
- `RateLimitResult.retryAfterSeconds` 由毫秒 PTTL 向上取整，至少为 1。
- 日志通过 SLF4J 输出到 Boot 默认控制台。启动时打印前缀、默认算法、默认额度；每次允许/拒绝打印命名空间、维度、算法、额度、等待时间与耗时。默认输出形态：

  ```text
  INFO  ... -- common-rate-limit 已启用：basePrefix=cp:local:identity-service:rate-limit:v1:, defaultAlgorithm=fixed-window, ...
  INFO  ... -- 限流放行：namespace=identity:login, dimension=account, algorithm=sliding-window, limit=5, window=300000ms, remaining=4, elapsedUs=812
  WARN  ... -- 限流拒绝：namespace=identity:login, dimension=account, algorithm=sliding-window, limit=5, window=300000ms, retryAfterSeconds=42, elapsedUs=744
  ```

- **日志不含原始标识、SHA-256 摘要、完整 Redis 键或 Redis 凭据**。Redis 异常默认只记录异常类名，完整堆栈需要把 logger 调到 DEBUG。
- `cloudprocure.rate-limit.log-decisions=false` 关闭允许/拒绝决策日志；Redis 故障的 ERROR 不受影响。
- 日志是 UTF-8；Windows 控制台若显示乱码，先执行 `chcp 65001` 或使用 UTF-8 终端/IDE 控制台。

## 8. 自动配置与配置元数据

- 自动配置类：`RateLimitAutoConfiguration`，排在 Boot 的 Redis 自动配置之后。
- 自定义 `RateLimiter` 时默认 Redis 限流器退让；自定义 `RateLimitKeyResolver` 时默认解析器不被使用；自定义 `RateLimitDecisionLogger` 时默认日志器退让。
- 默认 `RateLimitKeyResolver` 在默认限流器内部按需创建，不单独注册 Bean，因此应用提供自定义 `RateLimiter` 时不会因为缺少 `spring.application.name` 被迫失败。
- AspectJ 缺失时只跳过 AOP，程序化 `RateLimiter` 仍可用。
- 配置元数据由 `spring-boot-configuration-processor` 生成；`additional-spring-configuration-metadata.json` 补充中文描述与算法值提示。
- Lua 脚本固定在 `classpath:lua/*.lua`，不提供“脚本资源位置”配置项：替换脚本会破坏返回三元组和 fail-closed 契约，应由代码评审和测试控制，而不是运行时配置。这是最终决定，不是待补齐项。
- 失败策略固定 fail-closed，不提供 fail-open 开关；这是最终安全取舍，不是遗漏。
- 根 POM 新增 `spring-boot.version` 属性，仅用于注解处理器路径这类无法继承父 POM 版本的位置；须与 `spring-boot-starter-parent` 版本保持一致。

## 9. 验证与已知边界

本次验证：

- 38 个单元测试：key/配置校验、SpEL 白名单、AOP 合并与 self-invocation/private 边界、注解算法传递、自动配置退让与缺 Redis 启动失败、连接异常 fail-closed；
- 10 个真实 Redis 集成测试（Docker `cloud-redis`，Redis 7.4.7；NOSCRIPT 用独立临时 Redis）：四种算法并发不超发、固定窗口拒绝不递增/不续 TTL、过期恢复、两实例共享额度、损坏值/缺失 TTL/WRONGTYPE fail-closed、Retry-After 向上取整、脚本缓存清空后的 EVAL 回退。
- 测试源码按仓库约定只保留本地（`.gitignore` 忽略 `**/test/`），干净克隆的 `verify` 不会执行这些测试。
- 运行集成测试：设置 `REDIS_INTEGRATION=true`、`REDIS_PORT`，有密码时设置 `REDIS_PASSWORD`，例如 `mvn -pl common/common-rate-limit test`。

未验证/不支持：

- Redis Cluster/Sentinel、跨槽多键事务、故障转移和代理来源识别；
- WebFlux 事件循环调用；
- 生产压测、容量与 SLO；
- 验证码、永久锁定、自动解封、分布式锁；
- 多维度原子扣减（当前为保守多消耗）。

运维风险：

- Redis 的 `maxmemory` 淘汰策略可以删除限流键，等于重置额度。限流键所在实例应使用 `noeviction`，或与缓存实例隔离；否则“设置了 TTL”不代表计数不会被提前淘汰。
- 阻塞 Redis 调用会占用请求线程。`spring.data.redis.timeout` 必须配置为短超时（例如 2s），否则 Redis 故障会拖垮线程池；超时最终仍转换为 `RateLimitUnavailableException`。
- 使用 Redis 服务器 `TIME` 可以避免应用机器时钟漂移，但不能防御 Redis 主从切换造成的服务器时间异常；这类故障按 fail-closed 处理，需要监控。
- 同一方法的多维度（例如账号 + 来源）是两次脚本，不是跨键事务；发布/切换算法时旧键可能短暂保留，按新算法重新计数。
- 类级注解只对实际被代理的类生效；把注解放在接口/父类上时，JDK 代理与 CGLIB 的匹配行为不同，建议把注解放在实现类方法上并补测试。

## 10. 与 issue 的差异与阶段 2

- issue 的注解草图使用 `Duration window()`，Java 注解不支持，本实现改为 `String window()`。
- issue 阶段 1 只要求固定窗口；本实现按本次需求扩展了滑动窗口、令牌桶、漏桶，并在键中加入算法段。
- `RateLimitResult` 增加 `remaining` 字段，同时保留 issue 的两参数构造方式。
- 注解增加 `dimension` 属性，便于显式区分同一方法的不同业务维度。
- identity 阶段 2 已迁移到本模块程序化 API，见[19 identity登录限速迁移](19-identity登录限速迁移.md)。identity 先把账号 trim 并做固定长度摘要，再交给 `RateLimitKey`；最终键包含 `rate-limit:v1` 与算法段，和 issue 中的示例字符串不完全相同。
- 变更已提交到 `master`，Issue #12 以 `completed` 关闭；测试源码仍只保留本地。
