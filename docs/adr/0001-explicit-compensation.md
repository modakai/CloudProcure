# 用本地事务与显式补偿协调采购、资金和履约

状态：accepted（设计采纳，尚未实现）｜日期：2026-10-20｜对应决策登记ADR-007。

采购从内部审批延伸到外部支付与实物发货，生命周期远长于数据库事务；外部扣款与已发生的发货不能通过数据库回滚撤销。主线采用每个服务本地事务、Outbox/Inbox、持久化流程任务和显式补偿，以各服务的事实与业务栅栏协调最终结果，Seata仅用于隔离的事务对照实验。

这个选择付出的代价是必须实现支付未知状态、先冻结再退款、关闭与释放墓碑、重复消息去重、对账和人工恢复，不能把“最终一致”当作暂时不处理失败的理由。单纯同步调用或无持久化的内存事件不能满足宕机恢复要求；跨服务长事务也不能代替真实渠道的查单和退款。具体状态与恢复规则见[核心流程与一致性](../07-核心流程与一致性.md)。
